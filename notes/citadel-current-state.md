## Current Security Controls

### SSH

- OpenSSH server is installed and active.
- SSH is used for remote administration.
- Password authentication is disabled.
- Keyboard-interactive authentication is disabled.
- SSH key authentication is used.

### UFW

- UFW firewall is active.
- Logging is enabled.
- Default incoming policy is deny.
- Default outgoing policy is allow.
- Routed traffic is denied.
- SSH on port 22 is allowed.
- Tailscale interface traffic is allowed.

### Fail2Ban

- Fail2Ban is installed and active.
- sshd jail is enabled.
- Fail2Ban monitors `/var/log/auth.log`.
- Fail2Ban has detected failed SSH login attempts.
- Fail2Ban has banned offending source IPs.

### Cloudflare Tunnel

- Tunnel name: `citadel-tunnel`
- Cloudflared is installed through APT.
- Cloudflared runs as a system service.
- Cloudflared is enabled at boot.
- Cloudflare Tunnel provides public access without traditional router port forwarding.

### Tailscale

- Tailscale is configured for secure remote administration.
- Remote administration has been tested from iPhone.

## Current Local AI Stack

Ollama is installed and used for local model execution.

Ollama is currently started manually with:

`nohup ollama serve > ~/.ollama/ollama.log 2>&1 &`

Ollama is not currently installed as a systemd service. Creating an Ollama systemd service is a future improvement.

Installed local models:

- `llama3.2:3b`
  - Current primary Odysseus Memory Core response model.
  - Used for faster local RAG responses.

- `llama3.1:8b`
  - Larger local general-purpose chat model.
  - Higher quality potential, but slower on the current VM.

- `qwen3:8b`
  - Local reasoning/chat model.
  - Candidate for quality mode, but may be slower or less consistent in the current RAG setup.

- `nomic-embed-text`
  - Local embedding model.
  - Used by Odysseus Memory Core to embed Citadel notes, documentation, and project pages.

## Odysseus Memory Core Current State

Odysseus Memory Core v0.1 is operational as a terminal-based local RAG prototype.

Current RAG flow:

Citadel notes/docs  
↓  
`rag/ingest.py`  
↓  
`nomic-embed-text` embeddings  
↓  
ChromaDB vector database  
↓  
`rag/query.py`  
↓  
`llama3.2:3b` response model  
↓  
Citadel-specific answer

Current files:

- `notes/odysseus-briefing.md`
- `notes/citadel-current-state.md`
- `rag/ingest.py`
- `rag/query.py`
- `odysseus`

Current wrapper command:

`./odysseus "What is The Citadel project?"`

Current RAG configuration:

- Embedding model: `nomic-embed-text`
- Chat model: `llama3.2:3b`
- Vector database: ChromaDB
- Retrieval count: `n_results = 2`
- Output limit: `num_predict = 180`
- Temperature: `0.2`
- Thread count: `num_thread = 4`
- Keep alive: `30m`

Performance tuning notes:

- The VM currently sees 6 CPUs.
- 6 model threads performed worse than 4.
- `num_thread = 4` is the best current setting.
- Warm responses are much faster than cold starts.
- Warm response benchmark improved to around 20-21 seconds during tuning.
